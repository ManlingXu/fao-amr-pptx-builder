# V2 — AI 规划故事线、多轮调整和 PPT 模板

**当前状态：** 已实现后台规划、保存、修订和按确认方案生成 PPT 的代码，提供可运行的合成数据演示。Copilot Studio 内的 Agent 对话流程与 Teams 发布仍需在 FAO 的批准环境中配置和验证，不能写成“已经上线”。

## 1. V2 的目标

V1 主要是“搜索现有幻灯片—核对日期—选页确认—生成可编辑初稿”。V2 在此基础上增加**一份可以保存和修改的章节规划**：Copilot Studio 中的 AI 理解会议用途和受众，先拟定故事线，再按各章节检索现有资料，最后经过用户确认生成 PPT。AI 不编造专业数据，不凭空生成来源不明的新页。

**例子：** 同事要求做一份供非洲兽医主管部门使用的 AMR 演示。AI 提议背景、监测、FAO 工作、下一步重点四个章节，并搜索对应的 PPT。用户随后说“背景少一点，近期活动放前面”，AI 再调整结构和选页顺序。用户审核最新版本后，才会生成文件。

如果某个章节搜不到足够的页，系统会标注**资料不足（gap）**；不会悄悄虚构内容。当前后台检索以关键词为主，AI 可以通过同义表达、专业术语和多章节查询改善查找效果，但不能宣称已经有语义向量检索服务。

## 2. 新增四个 Copilot 工具

| 工具 | 作用 | 必要条件 |
|---|---|---|
| `PlanPresentation` | 分章节创建、检索并保存规划 | 标题、受众、用途、各章节名称／关键词／目标页数 |
| `GetPresentationPlan` | 读取规划的最新版本 | 规划 ID；必须是本人创建 |
| `RevisePresentationPlan` | 多轮调整章节、选页和顺序 | 规划 ID、当前版本号、完整的新章节清单 |
| `CreateDraftFromPlan` | 按最终确认的版本生成可编辑 PPT 初稿 | 最新版本号以及用户明确同意 |
 
前一版的搜索、版本比较、上传模板、直接建稿、更换模板、查询完成状态六个工具仍保留，总计 **10 个可供 Agent 调用的工具**。

## 3. 模板功能的实际边界

现有代码可让用户上传自己的 PPTX/POTX 模板，为新初稿或已生成文件应用模板母版、主题和布局，并保留可编辑内容及来源对应表。**这并不代表复杂内容能自动重新设计成完美统一的 FAO 风格。** 含复杂图表、排版、备注的页面仍需桌面 PowerPoint 检查。V2 规划中可以记录所选模板；在后续修改故事线时，未指定新模板会默认保留原选择。

## 4. 本地检查

在仓库根目录安装 `.[test]` 后运行：

```bash
python -m pytest
python scripts/run_storyline_demo.py
python scripts/run_template_demo.py
```

演示会在 `examples/output/v2/` 生成故事线 JSON、来源对应表和可编辑 PPT。使用**合成测试文件**，不调用 LLM 或 Microsoft 组织服务。

## 5. CSI 仍需落实

组织级发布仍需：有效 Copilot Studio 权益、批准的环境／工具连接策略、API 后台运行主机与 HTTPS 地址、Entra/Graph 授权、SharePoint 资料源和输出路径、Teams 分享与安装政策，以及费用／运维负责人。上述事项无法通过把 Python 代码上传 GitHub 自动获得。

接手人应先读 [Copilot Studio 配置](COPILOT_STUDIO_CN.md)、[CSI 交接](CSI_HANDOFF_CN.md) 和 [验收清单](ACCEPTANCE.md)。`integrations/copilot-studio/flow-design.json` 是**流程蓝图，不是可以直接导入的 Agent**；要在真实租户中配置主题变量、用户确认、四个新工具和错误处理。

**限制：** 不具备完全语义检索、全自动美化、自动生成新科学事实或报告图表的功能；日期和版本判断需要人工把关。仓库是公开的，请勿上传未经批准的 FAO 文件、密码、密钥或真实人员资料。
